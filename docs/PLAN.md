# PLAN.md — «Hill Racer» (рабочее название)

2D-гонка по холмам в духе Hill Climb Racing 2. Своя, без рекламы и IAP.
Этот документ — план по фазам для Claude Code. Одна фаза = одна задача/сессия.

---

## 0. Ключевые решения (мини-ADR)

**Платформа:** web-first (браузер), затем Android через Capacitor.
Причины: стек Павла (TypeScript/Node/Angular), мгновенная итерация через dev-сервер, Claude Code может сам «видеть» игру через headless-скриншоты и гонять физику в Node-тестах. APK получаем позже без переписывания.

**Стек:**
- **TypeScript + Vite** — сборка и dev-сервер.
- **Phaser 3** — рендер, сцены, ввод, загрузка ассетов, камера, звук.
- **planck.js** (порт Box2D) — физика. Ключевой аргумент: `WheelJoint` из Box2D (подвеска-пружина + мотор в одном джоинте) — это буквально эталонная «car demo» Box2D, ровно этот жанр. Matter.js (встроенный в Phaser) отвергнут: мягкие constraints дают дрожащую подвеску и плохое сцепление колёс.
- **vitest** — юнит- и интеграционные тесты (planck работает в Node — физику можно тестировать без браузера!).
- **playwright** — headless-скриншоты игры для визуальной проверки.

**Альтернатива (не выбрана):** Godot 4 — если бы нужен был нативный APK/exe сразу. Минусы: сложнее автотестирование для Claude Code, вне основного стека.

**Правовая ремарка:** копируем механику (механики не защищаются), но никаких ассетов, названий, логотипов и персонажей Fingersoft. Своё имя, свои текстуры (ChatGPT), свой стиль.

## 2. Технические инварианты (нарушать нельзя)

1. **Физика в метрах.** Box2D стабилен на объектах 0.1–10 м. Машина ≈ 2 м. Конверсия в пиксели только в слое render: `PX_PER_M = 50`, видимая ширина мира ≈ 18–26 м (камера с zoom-out от скорости).
2. **Fixed timestep 1/60** с аккумулятором. Физика не зависит от FPS рендера.
3. **`src/core/` не импортирует Phaser.** Вся генерация, топливо, флипы, апгрейды, сейвы — чистые модули, тестируемые в Node.
4. **Детерминизм:** одинаковый seed ⇒ одинаковый рельеф, монеты, канистры. Обязательный тест.
5. **Никаких магических чисел в физике** — все параметры машин/апгрейдов/этапов только в `src/data/*.ts`.
6. **URL-параметры отладки** (с фазы 1): `?seed=42&stage=countryside&auto=gas&debug=1` (auto=gas — автогаз для скриншотов, debug — physics debug draw).

## 3. Фазы разработки

### Фаза 0 — Каркас проекта (~вечер)

**Задачи:**
- `npm create vite@latest` (vanilla-ts), TS strict, установить: phaser, planck, vitest, playwright, eslint + prettier.
- Сцены-заглушки Boot → Preload → Game (пустой канвас 1280×720, счётчик FPS).
- Скрипт `npm run shot`: playwright chromium открывает `http://localhost:5173/?auto=gas&seed=42`, ждёт 4 с, кладёт скриншот в `./shots/`. Это главный канал обратной связи для Claude Code.
- `npm test` — vitest с одним smoke-тестом.
- Положить CLAUDE.md в корень, git init, первый коммит.

**Критерии приёмки:** `npm run dev` показывает канвас с FPS; `npm test` зелёный; `npm run shot` создаёт PNG.

---

### Фаза 1 — Машина и физика (ядро игры, ~1–2 вечера)

**Задачи:**
- `core/physics/world.ts`: мир planck, гравитация (0, 9.8), fixed step 1/60.
- Плоская земля: `Chain`-shape, friction 1.0.
- `core/physics/car.ts` — `createCar(world, params)`: шасси (полигон ~2.0×0.8 м), 2 колеса (круги r=0.35 м), на каждом `WheelJoint` с осью (0, 1): пружина-подвеска (frequencyHz / в новых версиях planck — stiffness+damping, сверить с установленной версией) + мотор на заднем колесе (4WD-флаг включает передний).
- Управление: газ = D/→/правая половина тачскрина, тормоз/задний ход = A/←/левая.
  - Газ: `enableMotor`, `motorSpeed = -maxWheelSpeed`, `maxMotorTorque = engineTorque`.
  - Тормоз: сначала торможение (motorSpeed → 0 с высоким торком), при остановке — реверс (медленнее).
  - Отпущено: мотор выкл, свободный накат + слабое сопротивление качению.
- **Управление в воздухе** (фирменная механика HCR): оба колеса не касаются земли ⇒ газ даёт угловой момент назад (нос вверх, backflip), тормоз — вперёд (frontflip). Реакция от раскрутки колёс есть и «бесплатно», но её мало — добавить явный `airTorque` из params.
- Голова водителя: sensor-fixture над кабиной; контакт сенсора с рельефом ⇒ событие `DEATH` («Водитель разбился»).
- Синхронизация тел → Phaser-спрайты (пока прямоугольники/круги через Graphics). Камера follow + lookahead по скорости + зум-аут от скорости.

**Стартовые параметры (Jeep) — в `data/vehicles.ts`:**

| Параметр | Старт | Макс (апгрейд) | Комментарий |
|---|---|---|---|
| Шасси | 2.0×0.8 м, density 150 (~240 кг) | — | полигон по силуэту кузова |
| Колесо | r 0.35 м, density 60 | — | |
| Трение колеса | 2.2 | 3.5 | апгрейд Tires |
| Торк мотора | 300 Н·м/колесо | 900 | апгрейд Engine |
| Макс. скорость колеса | 40 рад/с (~50 км/ч) | 70 | апгрейд Engine |
| Подвеска, частота | 3.5 Гц | 6.0 | апгрейд Suspension |
| Подвеска, демпфер | 0.7 | 0.85 | апгрейд Suspension |
| airTorque | 250 Н·м | — | флипы |
| 4WD | выкл | вкл, 40% торка на перед | апгрейд 4WD |

Это стартовые значения для тюнинга, не догма — крутить по ощущениям от скриншотов/игры.

**Критерии приёмки:** машина разгоняется, тормозит, едет назад; подвеска видимо пружинит при наезде на ступеньку из статических боксов; в воздухе крутится от газа/тормоза; приземление на голову ⇒ смерть. Интеграционный тест в vitest (без браузера): «машина с автогазом проезжает 50 м по плоскости за < 10 с симуляции».

### Фаза 2 — Процедурный рельеф (~1 вечер)

**Задачи:**
- `core/terrain/noise.ts`: 1D value noise, 2–3 октавы, seedable (свой PRNG типа mulberry32, без зависимостей).
- `core/terrain/generator.ts`: высота y(x) с профилем сложности — первые ~100 м почти ровно, дальше плавный рост: `amplitude = min(0.5 + x/400, 6)` м, `wavelength: 18 → 9` м. Параметры профиля — из `data/stages.ts`.
- `core/terrain/chunks.ts`: чанки по 48 м, шаг точек 0.75 м. Создавать 2 чанка вперёд от камеры, удалять за 1 позади (и Chain-тело, и графику).
- Рендер чанка: залитый полигон вниз (грунт) + полоса «поверхности» по кривой. Текстуры — в фазе 5, пока цвета.

**Критерии приёмки:** бесконечная езда 1000+ м, кадр < 16 мс, память не растёт. Тесты: детерминизм (seed ⇒ те же высоты), непрерывность на стыках чанков.

### Фаза 3 — Игровой цикл (~1–2 вечера)

**Задачи:**
- `core/gameplay/run.ts` — state machine: Ready → Driving → Dead | OutOfFuel → Results.
- **Топливо:** бак 100, расход ~3.3/с (полный бак ≈ 30 с). Канистры (sensor) каждые 120 ± 20 м, подбор = полный бак. Бак пуст ⇒ мотор глохнет; |v| < 0.3 м/с в течение 3 с ⇒ конец заезда.
- **Монеты:** группы по 6–12 шт каждые 25–60 м, вдоль поверхности на высоте +1.2 м; в ямах и на трамплинах — бонусные дуги.
- **Флипы:** пока машина в воздухе — интегрировать угловую скорость шасси; на приземлении `flips = floor(|Σ| / 2π)`, знак ⇒ back/front. Награды в `data/rewards.ts`: backflip 50, frontflip 50, комбо +50% за каждый следующий, airtime — 2 монеты/с после 1.5 с. Всплывающие тексты «BACKFLIP +50».
- **HUD** (отдельная сцена поверх Game): бар топлива с миганием при < 25%, монеты, дистанция.
- Экран результатов: дистанция, монеты, причина смерти, кнопки Restart / Garage.

**Критерии приёмки:** полный цикл заезда с результатами. Юнит-тесты: детектор флипов на синтетических данных, расход топлива, начисление наград.

---

### Фаза 4 — Гараж и прогресс (~1–2 вечера)

**Задачи:**
- `data/upgrades.ts`: 4 ветки как в HCR — Engine, Suspension, Tires, 4WD. По 10 уровней, цена `base × 1.35^lvl`. Функция `applyUpgrades(vehicleParams, levels)` — чистая, тестируемая.
- Сцена Garage: выбор машины (пока одна — Jeep, каркас под несколько), покупка апгрейдов за монеты, превью характеристик.
- `core/save/`: интерфейс `SaveStorage` (сейчас localStorage, потом Capacitor Preferences). Схема с `version` для миграций: `{version, coins, vehicles: {jeep: {owned, upgrades}}, selectedVehicle, selectedStage, bestDistance: {stageId: m}}`.

**Критерии приёмки:** Engine 3 заметно мощнее Engine 0; прогресс переживает перезагрузку страницы. Тесты: математика цен/применения апгрейдов, миграция сейва.

---

### Фаза 5 — Этапы и текстуры от ChatGPT (~1–2 вечера)

**Задачи:**
- `data/stages.ts`: Countryside, Desert, Moon (gravity 1.62 — отдельный кайф), Cave. Этап = параметры генерации + gravity + набор текстур + палитра параллакса.
- Подключить ассеты по `docs/ASSETS.md`: кузов, колёса (rotation = угол тела), голова водителя (визуально на «пружинке» — синус от ускорения, без физики), монеты, канистры.
- Рельеф: RenderTexture на чанк — тайл грунта + полоса поверхности вдоль кривой.
- Параллакс: небо + 2 слоя холмов + облака-спрайты.
- Если какого-то файла нет — placeholder из Graphics, не блокироваться.

**Критерии приёмки:** визуально «настоящая игра»; смена этапа меняет картинку и физику; скриншоты всех этапов.

---

### Фаза 6 — Звук и полировка (~1 вечер)

**Задачи:**
- Phaser Audio: луп двигателя с `rate` от оборотов колеса (главный звук игры!), монета, флип, смерть, подбор топлива, фоновая музыка.
- Частицы: пыль из-под колёс при пробуксовке/приземлении, выхлоп.
- Тряска камеры при жёстком приземлении. Пауза, настройки громкости, главное меню.

**Критерии приёмки:** звук двигателя реагирует на газ; mute работает; пауза не ломает физику.

## 4. Как работать с Claude Code по этому плану

Шаблон запуска фазы:

```
Прочитай CLAUDE.md и docs/PLAN.md. Реализуй Фазу N.
Сначала покажи план изменений по файлам и жди моего ок.
После реализации: npm test, npm run shot, покажи скриншот,
проверь критерии приёмки фазы и предложи commit message.
```

Рекомендации:
- Одна фаза = одна сессия/задача. В конце — коммит. Не смешивать фазы.
- После любой правки физики — `npm run shot` и сравнение серий скриншотов; числа физики менять только в `data/vehicles.ts`.
- Если Claude Code предлагает новую зависимость — спрашивать «зачем», базовый набор: phaser, planck, vitest, playwright, eslint, prettier.
- Тюнинг «ощущения» машины делать самому в игре, а Claude Code давать конкретику: «на горке 30° машина буксует — подними стартовый торк/трение».
